# Design lab generators

Every board in the Claude Design project **`85c2eefb-a239-4501-83a0-a24a4ccd7cae`**
("Workout Session Tracker App") is generated by one of these scripts. The `.dc.html`
files are build output — edit the generator, never the HTML.

## Regenerating

```bash
cd claudedocs/design-labs
python3 lab41.py          # writes lab41.html into the cwd
python3 gate.py lab41.html   # must print RESULT: READY before uploading
```

Several scripts import their neighbours (`lab10`, `lab11`, `lab14`, `lab22` all build on
`lab05.screen()`; `lab13` imports `lab08`; `lab19` imports `lab15`; `lab23` imports `lab20`; `lab29` imports `lab28`; `lab30` imports both; `lab31` imports all three; `lab32` imports `lab31`; `lab33` imports `lab31` and `lab32`; `lab34`–`lab41` import `kit`, `lab35`/`lab36` also import `lab39`, and `lab42` imports `lab34`, `lab35` and `lab37` so its comparison columns use the real rows — the exercise screen and the calendar are each defined once, there).
Importing a lab re-runs it and rewrites its own HTML — harmless, but it means the whole set
regenerates cheaply.

## Files

| | |
|---|---|
| `kit.py` | **The settled design system, as primitives — start here.** §0 of `../design-exploration.md` written as code: palette, spacing law, phone frame, W2 nav, header, section, list row, rail, chips, sheet, action bar, charts. `psec()` is the settled section (Lab 40 M4: lit plate, ruled label, inset separators); `psec(plated=False)` for content that has its own boundary (Lab 41). Micro-visuals: `tiles`, `delta`, `meter`, `spark`, `ring`, `bars`, and `chart()` — the one labelled column chart. `phone(scroll=N)` renders a screen already scrolled, for reviewing the tail of one longer than the frame. |
| `check_geom.js` | **Post-render geometry check.** Paste as the `browser_evaluate` function body against a served board; returns `[]` when clean. Catches core type crossing the ring's gold arc, body/sheet overflow, and — since round seventeen — a screen that under-fills or pushes a whole section below the fold, measured as the last child's bottom against the scroll box. None of it is visible to `gate.py`. Run it on every new board. |
| `gate.py` | **Pre-upload gate.** Balanced tags, no `""`, no attribute spanning a newline, no type below 11px. Never upload on a BLOCKED result. |
| `pal.py` | Contrast maths: `ratio(a, b)`, `lift(hex, bg, target)` raises HSL lightness until a colour clears a contrast target with hue and saturation held. |
| `palette_board.py` | Lab 04 |
| `lab05.py` | The shared live-session screen. `screen(cls)` returns one phone under a CSS skin class. Labs 10, 11, 14 and 22 all drive it. |
| `lab06.py` – `lab42.py` | One board each. See the table in `../design-exploration.md`. |

## Viewing

`file://` is blocked by the browser tooling, so serve locally:

```bash
python3 -m http.server 8731     # then open http://localhost:8731/lab41.html
```

## Two traps that have already cost time

1. **Python `%` formatting and CSS percentages.** Any literal `%` inside a `%`-formatted
   string must be `%%`. This has broken four separate generators. Prefer f-strings or
   `.replace()` for anything containing CSS.
2. **`%` binds tighter than `+`.** `'a' + b + 'c %s' % x` formats only the last fragment, so a
   `%%` in `b` survives into the output verbatim. This shipped a literal `width:100%%` once.
3. **The 256 KiB read cap** on `DesignSync.get_file`. Keep boards under ~250 KB or a
   read truncates and an edit-then-upload destroys the tail of the file.
